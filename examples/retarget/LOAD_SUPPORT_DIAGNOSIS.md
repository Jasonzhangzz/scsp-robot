# 承重失败：与 trigrasp 执行链的对照

本次检查对应 2026-10-15 本地源码与真实 DexYCB Sugar Box 回放。
力闭合和承重分别报告；不降低 DexForge 的物体质量、增大手指增益或注入物体力。

## trigrasp 实际依靠什么

`examples/mpc/franka/trigrasp/trigrasp.py` 的 position 分支有以下机制：

1. 接近阶段直接执行预抓取 IK 位置目标，接近接触后才交接接触 MPC。
2. `plan_contacts` 携带上一周期的位置伺服目标，避免每周期重置到实测关节而丢掉预载。
3. 实测接触力校正 SCM 力输出的偏置和增益；`normal_pressure_command` 根据
   **有正有负**的预载误差增压或卸压。控制作用在手指上，而不是靠腕部单侧挤物体。
4. 在任务空间保持已建立的局部接触材料点，并显式评价整手运输候选。
5. 当前源码还使用力分配和 wrench 跟踪；这些不能按外部力目标接口照搬到本任务。
   这里由 MPC 内部的模型重力平衡和实际接触约束产生预载候选，Lambda 只提供接触点。
6. 实际闭合、有限力承重和持续接触用于确认抬升，独立抬升参考不会每次重新追随物体漂移。

源码默认物体质量为 **0.03 kg**；Sugar Box 场景质量为 **0.514 kg**，重量
**5.04234 N**。因此 trigrasp 默认每指 0.6 N 的压紧下限不能直接当成此场景的承重预算。
这不是降低质量的理由，也不证明 Wuji 不能抬升。

## 确认并修正的模型与控制错误

- **同指节接触被误当成语义材料点接触。** 原失败状态中，一些语义点仍离物体
  7–20 mm，却因为同一刚体有别的表面接触而被标记为已接触。SCM 使用真实 patch，
  接触代价和预载运动却使用远处材料点。现在执行材料点来自真实 patch 的手侧表面，
  在接触期间保留；原始 MANO 材料点仍独立保留为软目标。
- **模型验证与候选排序使用不同物理。** 原先原生仿真只修正第一步并检查末端闭合，
  主要排序分数来自剩余 SCM 轨迹。现在完整 horizon 的任务分数和力代价均由
  原生 MuJoCo 轨迹及实际接触力评价；SCM 保留作 RTI 求解、梯度和候选生成。
- **移除外部 wrench 时遗漏内部承重目标。** 几何法向覆盖并不约束实际力抵消
  重力。现在包含模型内部的 `sum(F_hand)+m*g` 和相应重力矩软代价，运行及终端
  都包含预载偏好。它不是 `plan` 的 wrench 输入，也不跟踪 Lambda 的力。
- **对向覆盖差时反而降低预载。** 现在按重量、实际接触数和原生金字塔的
  内切摩擦半径 `mu/sqrt(2)` 计算软预载预算，覆盖只用于诊断。
- **只增压，不能重新分配。** 新增 MPC 内部的静力预载候选：使用当前真实接触、
  原生切向基、物体重力、实际位置伺服控制范围和关节力矩限求平衡。它仅生成双向
  手指位置运动候选；是否执行仍由原生 horizon 的任务代价、碰撞和闭合检查决定。
  求解失败不阻断已有接触动力学，也不修改真实控制器的增益或力矩限。
- **同一刚体不同接触法向被合并。** 无名指末节可同时碰盒子的两个面。
  实际不同法向现在使用独立同刚体槽位；同 patch 的重复 collider 则合并。
  预载候选按实际 patch 而非单一主法向构造，原生有限差分候选补充真实伺服的
  跨 patch 力敏感性。槽位不足仍显式报告，不能把 SCM 称为完整 MuJoCo 动力学。
- 显式增加整体运输以及预载与运输组合候选；没有把任何候选作为强制执行的动作。
- 手部时钟播完后继续当前帧软跟踪和物体跟踪；只有实际终态达标或达到预算才结束。
  物体终态位置/旋转判据用于任务结束，未用于触发 Lambda FPS，也不约束手形误差。

## 已完成的独立证据

中间版 v5 完整序列：`outputs/wuji_physical_patch_142802`，81 控制周期、243 个
10 ms 物理步、69/69 个手部参考帧。原生控制重放位置误差为 0。

| 指标 | 修改前 v4 | 中间版 v5 |
| --- | ---: | ---: |
| 实际原生闭合物理步 | 1/243 | 113/243 |
| 最长连续原生闭合 | 0.01 s | 0.32 s |
| 最长连续保守闭合（mu=0.4，Fn>=0.05 N） | 0.01 s | 0.32 s |
| 实测有限法向预算下承重物理步 | 0 | 0 |
| 最大抬升 | 4.23 mm | 1.39 mm |

**闭合改善并不等于抬升通过。** v5 第 63 周期的代表状态：

- 实测接触的平衡承重上限为重量的 **0.3713 倍**。
- 同一组实际接触，在配置接触力限下几何上能承受重量的 **6.2487 倍**。
- 静力点接触模型同时考虑当前关节、实际控制范围和执行器力矩限，存在平衡完整
  重量的解。该解对拇指要求约 **3.36 N**；实测两个重复 collider patch 的总和约
  **1.09 N**。部分无名指 patch 已明显过载。这说明此状态需要重新分配压力，
  不能据此归咎于手的硬件能力，也不能只继续增加总压紧力。
- 该静力模型不包含关节限位和自接触的支撑反力，也不保证动态可执行；真正验收
  仍以位置控制产生的真实 MuJoCo 接触和抬升为准。

对应数据：`full/force_closure_audit/certificates.json` 的
`representative_static_witnesses`，包括逐 patch 的需求、实测力和所需关节力矩。

## 当前实测状态：短暂抬升成立，完整流程仍失败

2026-10-15 的最新完整运行 `outputs/wuji_material_load_142802` 已跑满 200 个
控制周期。逐 10 ms 重放 600 个物理步，与记录位置误差为 0：

- 原生摩擦锥下实际力闭合 0 步、实际承重 0 步；最大手部向上合力仅
  **0.632 N**，物体重量为 **5.042 N**。
- 最大物体中心高度增量 **1.78 mm**，不能认定为抬升成功。
- 手部参考停在第 29 帧，实际执行了 30/69 帧；离线几何 IK 仍覆盖全部帧。
  `object_task_completed=false`，结束原因为控制周期预算。
- Lambda 可行接触点不等于已经执行出来的接触。此运行中选定材料点尚未建立
  对应接触，实际接触组也没有闭合；不能把失败仅归为闭合裕度小。

独立承重续跑使用同一保存的真实抓持状态，但不同中间控制器版本，结果如下。
它们不能替代从 MANO 初始状态开始的完整验收，也不能证明最新控制器优于旧版。

| 续跑目录 | 物体中心最大抬升（相对续跑起点） | 结果 |
| --- | ---: | --- |
| `outputs/wuji_semantic_support_142802` | **26.55 mm** | 短暂抬起，随后失稳滑落 |
| `outputs/wuji_material_support_142802` | **0.82 mm** | 未承重；最长闭合 3.36 s，但最大实测法向预算承重能力仅为物重的 0.469 倍 |

对 26.55 mm 续跑进一步拼接原始位置控制前缀，逐 10 ms 物理重放：
`outputs/wuji_semantic_support_142802/physical_replay/full/force_closure_audit/certificates.json`。
672 个物理步的位置重放误差为 0，没有注入物体力。实际承重标准同时要求物体底部
离桌超过 2 mm、桌面支撑小于物重的 5%、实际手部重力平衡残差小于 20%。
满足标准的最长连续段为 **0.26 s**；其中同时保持原生力闭合证书的最长段仅
**0.05 s**。因此短暂离桌已得到实测支持，稳定闭合抬升仍未通过。

这里要区分两个失败：完整流程尚未建立目标闭合抓持；独立续跑能够短暂承重，
但接触和压力分配在运输期间不能持续维持。闭合证书只说明接触摩擦锥的几何性质，
不保证当前有限压紧力足够，更不保证位置伺服能在运动中持续实现该力分布。
