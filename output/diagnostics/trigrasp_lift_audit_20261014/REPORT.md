证据范围：以下结论针对当时 trigrasp 的 AllegroOnlineContactModel 接入及该次 rubber_duck 运行，不是新版 softSCM 算法的整体精度评估。该接入的驱动响应、摩擦锥和预测几何尚未与新版默认路径一致，不能将观察到的差异直接归因于 softSCM 核心。

本轮排查确认：“真实接触 → MPC 预测 → 可执行的手部运动/接触力”链路存在未对齐项目；现有对照还没有证明哪一项是抓取失败的主要原因。当前样本的 Lambda 选点和真实接触均能通过相应的几何力闭合/独立承重检验，但这不保证手部驱动可以实现这些理想接触力。trigrasp 也没有完整对齐 test_mpc_isaac.py 当前默认使用的接触预测模型。

所有主实验使用默认物体 rubber_duck、质量 0.03 kg、4 指、h=0.025 s、预测长度 4；关闭窗口、截图和视频。原始完整 MPC 运行 450 步，没有人为移动物体。对照实验从第 115 步保存的同一个真实抓取状态启动。诊断控制仅用于定位原因，没有替换生产控制器。

| 检查 | 实测结果 | 含义 |
|---|---:|---|
| 启动计划接触点 | 力闭合成立、wrench rank=6、承重可行 | 选点不是“根本不能闭合” |
| 第 115 步真实接触，使用 MuJoCo 实际四射线摩擦锥 | 力闭合成立 | 不只是理想接触或圆形锥下的证书 |
| 按当前实测法向力上限，独立 LP 可提供的竖直接触合力 | 约 1.992 N | 摩擦容量足够，但这是独立接触力的容量，不是手部驱动可实现性的证书 |
| 物体重力 | 0.2943 N | 抬离桌面需要手提供相应合力与力矩 |
| Lambda 理想指腹合力 Fz | 0.3382 N | 理想受力可驱动物体向上 |
| MPC 预测指腹合力 Fz | 0.04695 N | 模型没有预测出所需的向上支撑 |
| 实际指腹合力 Fz | 0.01961 N | 四指接触并不等于实际施加了抬升 wrench |
| 实际桌面支撑 Fz | 0.26178 N | 桌面仍承受主要重力 |
| 实际其他手部几何接触 Fz | 0.00970 N | 还存在指腹以外的接触 |

接触力转换的方向、坐标系和力矩原点已与 MuJoCo 的物体 qfrc_constraint 全量核对，450 帧的误差接近浮点舍入级别；上述差异不是把桌面支撑误算成了手的力，也不是 normal force 与 Fz 混用。

进一步对同一状态做了三个独立检查：

1. 在原有命令上下界内，多初值优化接触模型的指腹向上合力，找到约 0.06154 N；优化跟踪 Lambda 指腹力，得到约 0.05419 N。两者均低于重力。这些是数值搜索结果，并非全局上界证明。
2. 对原 MPC 的同一个完整目标做 100 次非线性优化迭代，目标从 1356.65 降到 1332.41，预测仍向下运动，状态和命令没有越界。求解达到迭代上限，不能据此断言全局最优；但未发现“换一个收敛充分的求解器即可实现抬升”的证据。
3. 将接触 Gauss–Seidel 扫描次数从 8 提高到 64，预测 Fz 从 0.04695 N 变到 0.04637 N。该状态的主要差异不是 8 次接触求解严重不收敛。

模型对齐检查：

| 项目 | test_mpc_isaac.py 当前默认路径 | trigrasp 当前路径 |
|---|---|---|
| 真正使用的模型 | CartesianRigidContactModel，19 维速度状态 | AllegroOnlineContactModel，79 维关节/速度/servo-target 状态 |
| 底层接触求解 | grouped_contact_velocity_cs，耦合法向与圆形库仑切向盘 | 相同底层函数 |
| 接触响应 | 0.01 s 物理接触响应；默认 legacy 分支还混合稳态接触 mobility | 单一 0.05 s 响应，没有稳态混合 |
| 预测几何 | 每个预测姿态更新法向、力臂与 gap | 更新一阶 normal gap，Jacobian/法向/力臂冻结 |
| 驱动响应 | Cartesian OSC 的有限时间 PD 响应，指数积分 | 关节位置 servo 的 backward Euler、对角有效惯量 |
| Lambda | 当前 Franka CSO 的摩擦锥为 pyramid；shared-contact-dynamics 为显式可选实验 | 多指 BatchedLambdaLM 使用圆形 Coulomb，理想力直接作用于物体，不模拟手的驱动力映射 |
| 仿真摩擦 | PhysX 材质平均合成；当前默认 fingertip/object=1.2，table/object=0.7 | MuJoCo 材质最大值合成，默认 2.5；场景未显式设置 cone，实际为 pyramidal |

需要区分底层接触定律复用与完整模型对齐。两种硬件与执行器的状态不同，不应直接把 Franka 三维 Cartesian 模型替换进 Allegro；但新版的接触响应、几何传输和稳态预载机制尚未适配到 Allegro。

摩擦锥差异有直接证据：第 115 步 Lambda 的理想力，在 index/ring/thumb 三个接触上超出实际 MuJoCo 摩擦金字塔，比例分别约 1.05、1.41、1.40；这些力仍满足圆形 Coulomb 锥。真实接触的四射线 LP 仍可找到另一组承重力，所以这不是“任何受力分配都不可行”，而是当前理想力与执行模型不一致。

同状态的控制对照进一步说明不能只改摩擦系数：

| 诊断执行方式 | 最大抬升 |
|---|---:|
| pyramidal，固定指关节并抬升手基座 | 1.29 cm |
| pyramidal，实测法向力反馈并抬升 | 1.78 cm |
| elliptic，固定指关节并抬升手基座 | 3.16 cm |
| elliptic，实测法向力反馈并抬升 | 17.31 cm，随后仍滑落 |

这些对照不包含完整 MPC，也不是可交付的抓取策略。它们说明匹配摩擦锥和维持真实预载都有明显作用；法向力反馈本身也不足以维持整个抓取轨迹，还必须跟踪接触迁移和物体力矩。完整 MPC 只切换 elliptic 后仍失败，最大抬升 0.78 cm，不能将该开关单独作为修复。

当前 MPC 没有把预测接触的力闭合/承重余量作为约束，实际证书仅作为外部 lift latch。力跟踪项还被 1/600 转换为位移尺度，权重默认为 1；该状态的一阶力残差成本约 5e-7，而完整 MPC 目标约 1e3。原来的目标更容易改善几何误差，无法保证维持预载或分配足够的向上 wrench。

本轮代码改动仅增加独立 wrench/容量诊断，并将 Allegro 原来硬编码的 SCM 时间、阻尼比、正则接入共享参数与 CLI，保持默认值和正常控制行为不变。没有为了得到成功结果而永久改变仿真摩擦、强加物体外力或恢复 IK 关节跟踪成本。

下一步修复应首先统一仿真、Lambda 和 MPC 的摩擦锥及力单位，并针对 Allegro 的耦合执行器适配新版接触响应/几何传输；再引入实测预载、可执行 wrench 和承重余量的预测控制。仅调 object pose 权重、增大摩擦系数或延长求解器迭代不能保证解决问题。

补充误差统计（同一原始 baseline.json，h=25 ms）：全量 450 步的单步物体位置误差中位数为 1.06 mm、95 分位为 2.87 mm；进入 loaded 的 65 步分别为 2.51 mm、5.72 mm。第 115 步同状态同命令的预测下降 0.737 mm，实测下降 0.042 mm，绝对差约 0.696 mm。实测位移接近零，不应使用两者的约 18 倍比值评价精度。当前证据足以说明该接入与执行尚有差异，不足以断言“当前 softSCM 预测偏差较大”，也没有证明该差异是抓取失败的唯一或主要原因。详见 prediction_error_statistics.json。
